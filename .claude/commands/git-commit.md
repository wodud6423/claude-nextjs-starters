# /git-commit

변경된 파일을 감지하고, 내용을 분석해 Conventional Commits 형식의 커밋 메시지를 자동으로 생성한 뒤 커밋한다.

`$ARGUMENTS`를 메시지 방향 힌트로 사용할 수 있다 (예: `/git-commit 로그인 버그 수정`).

## 실행 절차

### 1단계 — git 상태 확인

`git status`를 실행해 staged/unstaged 파일 목록을 파악한다.

- **staged 파일이 있으면** → 3단계로 바로 이동한다.
- **staged 파일이 없고 unstaged 파일만 있으면** → 2단계로 이동한다.
- **변경된 파일이 없으면** 아래 메시지를 출력하고 종료한다:
  ```
  커밋할 변경 사항이 없습니다.
  ```

### 2단계 — git add 선택

unstaged 파일 목록을 보여주고 사용자에게 선택을 요청한다:

```
다음 파일이 stage되지 않았습니다:
  M  src/components/Button.tsx
  M  src/lib/utils.ts
  ?  src/hooks/use-modal.ts

어떤 파일을 추가할까요?
  1) 전체 추가 (git add .)
  2) 파일 선택 (번호 또는 경로 입력)
  3) 취소
```

- **1 선택** → `git add .` 실행
- **2 선택** → 사용자가 입력한 파일만 `git add <파일>` 실행
- **3 선택** → 종료한다

### 3단계 — 커밋 메시지 자동 생성

`git diff --staged`로 변경 내용을 분석하고, `$ARGUMENTS`가 있으면 힌트로 활용해 아래 형식의 커밋 메시지 초안을 작성한다.

**Conventional Commits 형식:**
```
<type>: <한국어 설명>

[선택] 본문 — 변경 이유나 주요 내용 (필요 시)
```

**type 선택 기준:**
| type | 사용 시점 |
|------|-----------|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `chore` | 빌드, 설정, 의존성 변경 |
| `docs` | 문서 변경 |
| `refactor` | 기능 변경 없는 코드 개선 |
| `style` | 포맷, 공백 등 스타일 변경 |
| `test` | 테스트 추가 또는 수정 |

초안을 사용자에게 보여주고 수정 여부를 확인한다:

```
커밋 메시지 초안:
──────────────────────────────
feat: 로그인 폼 유효성 검사 추가
──────────────────────────────

이 메시지로 커밋할까요?
  1) 확인 (그대로 커밋)
  2) 수정 (직접 입력)
  3) 취소
```

- **1 선택** → 4단계로 이동
- **2 선택** → 사용자가 입력한 메시지로 교체 후 4단계로 이동
- **3 선택** → 종료한다

### 4단계 — 커밋 실행 및 완료

확정된 메시지로 커밋을 실행한다:

```bash
git commit -m "<확정된 메시지>"
```

완료 후 아래 형식으로 결과를 출력한다:

```
✓ 커밋 완료!
  해시: a1b2c3d
  파일: 3개 변경
  메시지: feat: 로그인 폼 유효성 검사 추가

다음 단계:
- 원격 브랜치에 push하려면: git push
```
